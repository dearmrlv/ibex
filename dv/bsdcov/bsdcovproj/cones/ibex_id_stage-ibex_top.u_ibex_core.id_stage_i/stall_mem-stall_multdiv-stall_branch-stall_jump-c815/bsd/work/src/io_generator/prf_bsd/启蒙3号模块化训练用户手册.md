该手册用于指导启蒙3号分模块训练，主要是根据启蒙3号模拟器“端口不明确”、“端口过多”以及“训练速度慢”这三个核心问题，提出的解决方案，由于时间紧、任务重，方案中的许多手段比较定制化，对问题解决可能缺乏一定普适性。

## 一、解析模拟器接口

在启蒙3号的后端中，接口采用结构体调用结构体的方式，甚至包含结构体指针以及各种数组（脚本仅支持二维数组），于是采用脚本形式解析结构体获取接口，于是，对接口规范提出了要求，要求如下：

①\_IN和\_OUT的class定义模块输入输出部分，递归结构体调用定义在config.h和IO.h中；

```
class ISU_OUT {
public:
  Iss_Prf *iss2prf;
  Iss_Dis *iss2dis;
  Iss_Awake *iss_awake;
};

class ISU_IN {
public:
  Dis_Iss *dis2iss;
  Prf_Awake *prf_awake;
  Exe_Iss *exe2iss;
  Rob_Broadcast *rob_bcast;
  Dec_Broadcast *dec_bcast;
};
```

②包含函数的主class名称与文件同名，通过XXX（输入）和XXX_1（输出）来进行寄存器定义；

③宏定义目前不支持复杂运算，仅支持define 宏名 宏值的定义方式。



下面将介绍如何进行接口提取。

#### ①准备模拟器模块接口相关头文件

将参与接口提取的所有.h放到simulator_script/interface_extractor/include下

例如：

├── include
   ├── config.h
   ├── IO.h
   └── ROB.h

#### ②修改Makefile

修改Makefile中“./include/  XXX.h”的XXX.h为需要解析接口的主头文件

例如：

```
python3 ./advanced_interface_analyzer.py  ./include/  ROB.h
```

#### ③进入conda环境，执行make命令

```
conda activate qm
make run_python
```

生成的xxx_bsd.h为接口文件（用于启蒙3号的模块训练）

## 三、构建io_generator

这一步主要是将“**模拟器中的模块代码**“以及“**接口生成脚本生成的代码**“”进行结合，用于BSD训练过程中的io_generator的构成。

#### ①组织文件结构

在BSD仓库的io_generator目录下新建文件夹rob_bsd，用于存放模拟器的io_generator；新建simulator_include用于存放模拟器相关代码。

```
mkdir XXXX/BSD/src/io_generator/rob_bsd
cp XXXX/simulator_script/interface_extractor/rob_bsd.h XXXX/BSD/src/io_generator/rob_bsd/
mkdir XXXX/BSD/src/io_generator/simulator_include
cp 需要训练的模块在模拟器中的相关代码 XXXX/BSD/src/io_generator/simulator_include
```

这里怎么判断哪些是相关代码呢？

通过阅读ROB.cpp开头包含了哪些头文件，一般就是需要拷贝过来的，但不一定全是（比如ROB.cpp中的\#include <RISCV.h>）；

或者通过报错判断缺少哪些头文件，就先把ROB.cpp弄过来，后面运行看看哪个过程缺失了头文件，就包含对应头文件（这里最好知道包含的头文件里面都是干嘛的，不要无脑搬运）。

比如ROB.cpp，就需要将IO.h、config.h、ROB.h、util.h也一并拷贝到ROBX/BSD/src/io_generator/simulator_include下；

但是TOP.h和RISCV.h则不需要。
